# Son of Orchestrator

## Overview

Ведёт продиктованную идею до работающего результата за один диалог. Человек
отвечает на вопросы в начале — и получает готовое. Он не читает спецификации,
не оценивает тикеты, не смотрит код.

Ядро то же, что у прародителя (Autopilot): **порядок — это и есть продукт.**
Код пишется в предпоследней фазе; всё, что раньше, — разбор задачи и визуальное
направление.

Отличие от Autopilot ровно одно и оно намеренное: **два обязательных
дизайн-гейта через Impeccable** — `shape` до нарезки тикетов и
`critique → polish` перед финальным отчётом. Раздача идёт без ручного ревью со
стороны автора, и без этих гейтов результат сползает в generic AI-slop.

**Скилл самодостаточен.** Правила всех фаз лежат в `phases/`. Единственная
внешняя зависимость — `impeccable`, и она нужна только ради того, ради чего
этот скилл вообще существует. Делегировать разбор и сборку наружу нельзя: в
`mattpocock/skills` навыки `to-spec`, `to-tickets` и `implement` помечены
`disable-model-invocation: true` — их запускает только человек слэш-командой, а
харнес прямо запрещает обходить это иными средствами. Пайплайн, построенный на
их вызовах, встанет на второй фазе, уже пройдя интервью.

## Когда использовать

- Человек диктует, что нужно построить, и ждёт результат — не совместную работу
  над процессом.
- Он не будет читать спеку, судить о размере тикетов, смотреть диффы (в том
  числе ученик курса без технического бэкграунда).
- «Собери под ключ», «just build it», «не задавай лишних вопросов».

**Когда НЕ использовать:**

| Ситуация | Что вместо |
|---|---|
| Хочет проектировать вместе, шаг за шагом | Веди обычный диалог, без фаз |
| Правка в одном файле | Просто сделай её |
| Идея огромная и туманная, цель неясна | Сначала разбери масштаб, потом сюда |
| Учится и хочет понять механику | Объясняй по ходу, это другой режим |
| Нужен разбор и критика готового | Это работа старшего — совета критиков |

## Артефакты

Фазы говорят друг с другом через файлы, а не через диалог: на фазе сборки у
субагентов чистый контекст, и диалога они не видели.

```
.orchestrator/
  interview.md   расшифровка Фазы 1 — вопросы и ответы дословно
  spec.md        Фаза 2
  shape.md       Фаза 3 — визуальное направление от impeccable
  tickets.md     Фаза 4
```

Папка создаётся в корне проекта и коммитится вместе с кодом. Человеку про неё
говорить не нужно — она для тебя и для субагентов.

## Пайплайн

Каждая фаза — отдельный файл правил. **Читай файл фазы перед тем, как её
начать**, а не по памяти.

| Фаза | Файл | Что делает |
|---|---|---|
| 0 | [phases/0-preflight.md](phases/0-preflight.md) | Проверка окружения, установка `impeccable` |
| 1 | [phases/1-interview.md](phases/1-interview.md) | Вопросы — единственный гейт для человека |
| 2 | [phases/2-spec.md](phases/2-spec.md) | Спека из расшифровки |
| 3 | [phases/3-shape.md](phases/3-shape.md) | Дизайн-гейт: `impeccable shape` |
| 4 | [phases/4-tickets.md](phases/4-tickets.md) | Нарезка на задачи |
| 5 | [phases/5-build.md](phases/5-build.md) | Сборка: один тикет — один субагент |
| 6 | [phases/6-finish.md](phases/6-finish.md) | Дизайн-гейт `critique → polish` и отчёт |

Порядок жёсткий. Фаза 3 стоит до нарезки не для красоты: тикеты, трогающие
интерфейс, режутся с оглядкой на визуальное направление, иначе оно приедет
постфактум и переписывать придётся сделанное.

## Отмазки — СТОП

| Отмазка | Реальность |
|---|---|
| «Сказал не задавать вопросов» | Он сказал не задавать ЛИШНИХ. Решающие вопросы — часть работы. |
| «Проще сразу собрать» | Простой результат даёт порядок, а не пропуск этапов. Без спеки каждая правка — «я имел в виду другое». |
| «Дизайн и так норм, пропущу shape» | Эти гейты и есть отличие скилла от generic AI-slop. Раздача идёт без личного ревью автора. |
| «Critique нашёл мелочи, можно закрыть глаза» | Это детектор, а не совет. Повтор до чистого результата. |
| «Сделаю заглушку, потом уточнит» | Блокирующее — оплата, ключи, хостинг — решается в интервью, до сборки. |
| «И так понятно, что нужно» | Понятно тебе — не зафиксировано. Спека это единственная точка сверки. |
| «Быстрее всё в одном контексте» | Быстрее в первый час. Дальше модель ходит кругами и ломает то, что работало. |
| «Он не поймёт технических деталей, не буду отвлекать» | Не поймёт детали — но решение про оплату и хостинг принимает он, а не ты. |
| «Спека маленькая, помещу в голову» | Субагент на сборке в твою голову не заглянет. Нет файла — нет фазы. |
| «Субагент написал, что всё проверил» | Он проверил то, что ты назвал в строке проверки. Остального он не проверял и об этом не знает. |
| «Стек очевиден из типа проекта» | Тип проекта говорит, кто правит контент. Он молчит о том, сколько там движения. Два разных вопроса, два разных стека. |
| «Тот агент вроде закончил» | «Вроде» — не проверка. Два агента на одном файле затирают друг друга молча. |

## Красные флаги — начни фазу заново

- Код пишется до того, как появилась спека.
- Тикеты нарезаны до прохождения `impeccable shape`.
- Финальный отчёт отдан человеку до чистого `impeccable critique`.
- Человека просят проверить тикеты, их размер или код.
- Две задачи в одном контексте субагента.
- Параллельные субагенты правят одни файлы.
- Тихое допущение, не помеченное как `PLACEHOLDER`.
- Оплата, ключи или хостинг всплыли на финише.
- Стек выбран молча — или выбран под правку контента, когда просили движение.
- Задача закрыта без прогона своей строки проверки.
- Задача закрыта по отчёту субагента, без просмотра результата.
- Агент запущен на файл, над которым ещё работает другой.
- Отчёт написан техническим языком.

**Нарушение буквы этих правил есть нарушение их духа.**
