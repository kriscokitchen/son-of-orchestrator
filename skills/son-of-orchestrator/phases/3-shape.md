# Фаза 3 — Дизайн-гейт: направление

Визуальное направление задаётся **до** нарезки задач. Одного строгого ТЗ для
этого мало: раздача идёт без ручного контроля качества со стороны автора, и без
направления каждое окно собирает свою типовую заготовку.

Направление выбирает человек — глазами, а не по описанию. Человек, который не
читает спеки, по `shape.md` дизайн не оценит; по карточкам с палитрой, шрифтом и
картинкой мира — оценит за минуту.

## Когда гейт применим

Есть хоть одна поверхность, которую видит человек, — экран, страница, письмо,
переписка с ботом. Тогда гейт обязателен.

Проект вообще без поверхностей — библиотека, скрипт, обмен данными между
системами — гейт пропускается. Запиши причину строкой в `spec.md`: финиш прочтёт
её и скажет в отчёте, что дизайн-гейт не проводился и почему. Иначе человек
решит, что получил проверенный результат.

## В режиме итерации

После первого финиша визуальная правда — `DESIGN.md` в корне проекта: его пишет
документатор `impeccable` из построенного (Фаза 6). Итерация добавляет к нему
только новое: экраны, которых не было, и то, что меняется в старых. Результат —
`iterations/iN/shape-delta.md`, в той же конкретике, что ниже. Направление
заново не выбирается: новый бросок перекрасит уже построенное, и итерация уйдёт
на переделку.

Не меняется ничего видимого — файл из одной строки «без изменений» и причина.
Окна тикетов должны видеть, что направление проверено, а не забыто.

## Порядок

**1. `PRODUCT.md`.** Нет — запусти `impeccable init`. Его интервью **не должно
повториться поверх твоего.** Отдай в init готовое: `interview.md`, `spec.md`,
`refs/refs.md`, решение по стеку. `impeccable` требует хотя бы один круг ответов
человека перед записью — **ответы Фазы 1 и есть этот круг**: человек уже ответил
на всё, о чём спрашивает init. Чего в них нет — спроси, не больше одного круга;
есть всё — запиши `PRODUCT.md` без вопросов. В демо 2.4 init спросил «верно ли
записан продукт» поверх готового брифа, и человек не понял, что от него хотят.

**2. `impeccable shape` на готовую спеку.** Для нового мира shape уходит в
new-work `impeccable`: бросок `concept-seed.mjs` назначает направление, и
человек выбирает на странице в браузере (`serve-question.mjs`) — карточки с
тезисом, палитрой, материалом, первым экраном и картинками мира из каталога
`impeccable`, плюс «перебросить» и «стандарт категории». Следуй правилам
`impeccable` там как есть, с двумя поправками навыка:

- **Референсы человека — закреплённый выбор, а не подсказка.** Человек сказал
  «вот так» и показал — это мир, закреплённый брифом, и он сильнее броска (так
  и в `impeccable`: «a user- or brief-pinned direction beats the roll»).
  Референсы-«куски» — шрифт отсюда, движение оттуда — идут в бриф как сигналы,
  а не как закрепление.
- **Картинок навык не генерирует.** Эскизов на карточках не будет — карточки
  остаются с палитрой и картинками каталога, это полноценный выбор. Макеты для
  утверждения даёт человек, если хочет (ниже).

Страница не открывается — нет браузера, панель без него, скрипт вышел с кодом
2 — или закрылась без ответа (`--wait` вышел с кодом 4), то же решение идёт
вопросом с вариантами, один раз: по варианту на карточку, с тезисом и палитрой
словами. Человек ответил не выбором, а новыми референсами — разбери их по Фазе
1 и реши заново, кусок это или закреплённый мир (спроси с вариантами).

**3. Эталон.** Человек дал макет экрана — это эталон этого экрана:
`.orchestrator/design/comp-<экран>.png`. Не дал — эталона пока нет, его даст
первый тикет с интерфейсом (Фаза 4, «Первый экран»). Эталон — только первые
экраны, которые человек утвердил; остальные экраны строятся по токенам и языку
утверждённого. Это осознанное ослабление «comp is king» из `impeccable`: эталона
на каждый экран у нас нет, и делать вид, что он есть, хуже.

**4. Результат — в `.orchestrator/shape.md`** (в итерации — в
`shape-delta.md`). Если shape вернул направление только в диалоге, перепиши его в
файл сам: окна, где пойдут тикеты, этого диалога не увидят.

## Что должно оказаться в shape.md

Достаточно, чтобы окно с чистым контекстом собрало экран в нужном мире и **не
решало ничего из этого само**:

- **Контракт направления** — пять блоков `impeccable` (THESIS, OWN-WORLD, STORY,
  FIRST VIEWPORT, FORM с ключом броска). Первый тикет с интерфейсом вписывает
  его комментарием в разметку, как требует `impeccable`.
- **Палитра** значениями, с ролями. **Тихие роли текста** — отдельной строкой:
  «вторичный `#6E6E6E` на `#0E0E10` — тихий намеренно». `shots.mjs` предупреждает
  о контрасте ниже нормы, и без этой строки окно «починит» решение направления.
- **Гарнитуры с ролями и способом подключения** — ссылка на CSS или файл.
  Проект должен работать без интернета (офлайн-файл, приложение в поле) —
  только файлы `woff2` в проекте, без ссылок на Google Fonts и другие серверы:
  иначе без сети текст молча уйдёт в системный шрифт. Лицензию шрифта на
  самостоятельное размещение проверь (OFL — можно).
- **Шкала размеров** — плавная, по методу utopia, из скрипта навыка:
  `node <scripts>/fonts.mjs scale --min 16 --max 18 --ratio 1.2 --max-ratio 1.25`.
  В `shape.md` — готовые `--step-N`, а не «крупный заголовок».
- **Движение** — тезис движения по `impeccable animate`: один фокусный момент,
  что движется при смене состояний и что не движется вовсе. Кривые и
  длительности значениями (например, выход `cubic-bezier(0.16, 1, 0.3, 1)` за
  400 мс), уважение `prefers-reduced-motion`. Библиотека — CSS, пока хватает;
  больше — `motion` (MIT, без React: `motion/mini` 3 КБ).
- **Иконки** — один набор на проект, названием.
- **Компоненты** — своя вёрстка или библиотека названием. Библиотечный
  компонент перекрашивается в мир направления: готовый компонент в состоянии
  по умолчанию внутри выбранного мира — промах.
- **Что делать нельзя** — приёмы, которые направление исключает.
- **Порог финиша** — 30 из 40 или выше, если человек сказал, что дизайн здесь
  главное. Записывается сейчас, а не вспоминается на финише.
- **Что нужно от человека** — картинки и тексты, которых нет: окна поставят
  `PLACEHOLDER`, и список уйдёт в отчёт.

Строчка «минималистично и современно» направлением не является: окно с чистым
контекстом соберёт по ней типовую заготовку. Если shape вернул такое, дожми до
конкретики, прежде чем идти дальше.

## Проверка шрифтов перед выходом

Гарнитуры действительно поддерживают язык проекта. Латинский образец из
референса ничего не говорит про кириллицу: у Fontshare кириллицы нет ни у одного
из ста семейств, у части Google Fonts тоже, и русский текст молча падает в
системный — видно только глазами.

Проверь каждую гарнитуру по отрисовке, из любого источника:

```
node <scripts>/fonts.mjs check "Manrope" --css "https://fonts.googleapis.com/css2?family=Manrope"
node <scripts>/fonts.mjs check "Своя" --file fonts/svoya.woff2
```

«НЕТ» — гарнитура годится только для латинских ролей (логотип, цифры) или
меняется на другую. Дешевле здесь, чем переверстывать после сборки.
