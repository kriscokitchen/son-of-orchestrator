# Son of Orchestrator

**Скажи словами, что нужно построить — получи готовый проект.**

Навык для AI-агентов. Берёт идею, задаёт вопросы на человеческом языке —
сначала о том, как у тебя всё устроено сейчас, потом о развилках, — дальше сам
пишет техзадание, задаёт визуальное направление, разбивает на задачи и собирает
проект. Читать спецификации и код не нужно. Проект может идти кругами: после
показа — следующая итерация по отзыву.

Последняя версия — 2.4. Что менялось от версии к версии — в разделе [Версии](#версии).

Проверен на Claude Code. Про остальных агентов — раздел
[Совместимость](#совместимость).

Младший в семье Culture of Orchestrating. Старший — совет критиков, который
спорит и ловит ошибки. Этот — строит.

## Дизайн-гейты

**Два обязательных дизайн-гейта** через Impeccable: направление задаётся до
нарезки задач, а результат вычитывается перед сдачей. Раздача идёт без ручного ревью со стороны
автора, и без этих гейтов проект сползает в типовую заготовку.

Направление выбирает человек — глазами: референсы он присылает на первой фазе,
мир выбирает по карточкам в браузере, первый экран утверждает как эталон, и все
экраны дальше сверяются с ним бок о бок. Шрифты проверяются на кириллицу по
отрисовке, шкала размеров и движение задаются один раз — окна тикетов их не
выбирают. Картинки навык не генерирует: их даёт человек, недостающее уходит ему
списком.

## Установка

**macOS и Linux:**

```
curl -fsSL https://raw.githubusercontent.com/kriscokitchen/son-of-orchestrator/main/install.sh | sh
```

**Windows, PowerShell:**

```
irm https://raw.githubusercontent.com/kriscokitchen/son-of-orchestrator/main/install.ps1 | iex
```

Оба ставят в `~/.claude/skills/` — навык доступен во всех проектах.

Только в текущий проект:

macOS и Linux:

```
curl -fsSL https://raw.githubusercontent.com/kriscokitchen/son-of-orchestrator/main/install.sh | sh -s -- --project
```

Windows:

```
$env:SOO_SCOPE='project'; irm https://raw.githubusercontent.com/kriscokitchen/son-of-orchestrator/main/install.ps1 | iex
```

В каталог другого агента — `--dir ПУТЬ` или `$env:SOO_DIR`.

Прежнюю копию скрипты не затирают: она уходит в `skill-backups/` рядом с
папкой навыков, с меткой времени. В самой папке навыков её не оставляют —
агент принял бы её за второй навык со старым описанием.

Нужен `impeccable` — единственная зависимость, ставится из корня проекта:

```
npx impeccable install
```

Навык проверит его наличие сам на нулевой фазе и скажет, если чего-то не
хватает. Больше ничего ставить не нужно: правила всех фаз лежат внутри, в
`skills/son-of-orchestrator/phases/`.

После установки перезапусти агента, чтобы он увидел навык.

### Необязательно: obscura для проверок поведения

[obscura](https://github.com/h4ckf0r0day/obscura) — лёгкий браузер для агентов,
запасной путь для `probe.mjs`: когда Chromium не запускается (не скачан, сломан,
не поднимается в копии фонового агента), поведение страниц — текст, поля,
ошибки консоли — проверяется на нём. Он не требует скачанного Chromium и
поднимается за доли секунды. Внешний вид, видимость и нажатия навык всё равно
подтверждает на Chromium: раскладка и шрифты у obscura свои.

Проверена версия 0.2.5. Сборка для macOS на Apple Silicon:

```
curl -fsSLO https://github.com/h4ckf0r0day/obscura/releases/download/v0.2.5/obscura-aarch64-macos.tar.gz
shasum -a 256 obscura-aarch64-macos.tar.gz
# fcca31eba4280cd67a2e226ef4b015e432d5c089f78cefd074ad12bbc8e23345
tar xzf obscura-aarch64-macos.tar.gz
```

Релизы obscura контрольных сумм не публикуют. Сумма выше снята навыком с
архива, который он проверял: она ловит подмену или порчу файла после проверки,
но не поддельный релиз — доверие здесь к самому проекту obscura. Не совпала —
не запускай. Бинарники подписаны только служебной подписью, macOS и агент
могут спросить разрешение на запуск.

Положи `obscura` и `obscura-worker` в одну папку и укажи путь в `OBSCURA_BIN`,
например в профиле оболочки: `export OBSCURA_BIN=~/bin/obscura`. Из `PATH`
навык obscura не берёт. `probe.mjs` при каждом запуске сверяет сумму бинарников
с проверенной сборкой и открывает в obscura только свои страницы — `file://` и
localhost. Другая версия — `OBSCURA_TRUST=1`. Без obscura всё работает на
Chromium.

## Как пользоваться

Открой агента в папке будущего проекта:

```
/son-of-orchestrator Нужен сайт-визитка для студии маникюра, с записью и галереей
```

Или просто опиши задачу словами — агент поймёт сам:

> Собери мне под ключ лендинг для клиента, не задавай лишних вопросов

Дальше отвечаешь на несколько вопросов в начале. Каждый — с вариантами и полем
для своего ответа; в вопросах о том, как у тебя всё устроено сейчас, варианты
берутся только из твоих же слов и документов. Остальное происходит без тебя.

Проект показан, пришёл отзыв или новая задача — следующий круг:

```
/son-of-orchestrator итерация
```

## Как это работает

Семь фаз, каждая — отдельный файл правил. Код пишется только после раздачи.

| Фаза | Что происходит |
|---|---|
| 0 | Проверка окружения — на месте ли `impeccable` |
| 1 | Вопросы в три слоя: последний реальный случай, проверка посылки, развилки. Блокирующее — хостинг, оплата, доступы — первым; то, что уже есть в твоих документах, не переспрашивается |
| 2 | Техзадание из твоих ответов. Неизвестное помечается `PLACEHOLDER` |
| 3 | Визуальное направление: палитра, шрифты, сетка — до нарезки задач |
| 4 | Разбивка на тикеты, одна команда проверки проекта, волны скриптом |
| 5 | Раздача: строки запуска по волнам, дашборд; тикеты — в твоих окнах или фоном |
| 6 | Дизайн-ревью до 30 из 40 или двух проходов, сверка попадания, отчёт без жаргона |

Результат каждой фазы ложится файлом в `.orchestrator/` внутри проекта:
расшифровка интервью, техзадание, направление, тикеты. Читать их не
обязательно — они нужны окнам, в которых выполняются тикеты.

## Тикеты, волны и дашборд

Каждый тикет — отдельный контекст. Скрипт раскладывает тикеты по волнам: что
можно делать сразу, что после чего, какие идут параллельно, потому что не
трогают общих файлов. Он же ловит ошибки нарезки — два параллельных тикета на
одном файле, цикл, пропущенную зависимость — и пишет `runbook.md` с готовыми
строками вида `/son-of-orchestrator T03`.

Дальше два способа, выбираешь ты:

- **в окнах** — вставляешь строки в новые окна агента, когда удобно;
- **фоном** — основное окно запускает готовые тикеты фоновыми агентами в
  отдельных копиях репозитория, сливает результат и отчитывается. У агента свой
  контекст, в основное окно приходит только отчёт.

После каждой волны фоновых агентов — короткий итог: что готово, что упало, что
ждёт твоего решения, что изменилось на экранах. Дальше — как ты выбрал один раз
при запуске: спрашивать после каждой волны, продолжать ли, или вести до конца
итерации и останавливаться только на ошибке или вопросе.

У каждого тикета в начале три строки: что считать готовым, зачем, почему так. Их первым
читает окно тикета и получает фоновый агент.

Дашборд открывается вместе с началом работы и обновляется в реальном времени —
окна пишут в общий `status.json` короткой командой под блокировкой, страница
подхватывает. В шапке — описание проекта в одну-две фразы, исходный бриф
свёрнут под ним. Показывает итерации строками («И2 7 из 7, попадание 92%»),
текущую фазу, тикеты по волнам со временем каждого и раскрываемым описанием,
вопросы, которые ждут твоего решения, итог последней волны, что можно
запустить прямо сейчас, а дальше два числа:

- **выполнение** — сколько тикетов закрыто;
- **попадание** — сколько требований из исходного брифа подтверждено как
  сделанные так, как ты просил.

Расхождение между ними и есть главная строка отчёта: сто процентов выполнения
при семидесяти попадания значит, что задачи сделаны хорошо, а поняты неверно.
Пока часть требований не сверена, попадание честно показывает основание —
«сверено 6 из 9», а не округлённый процент.

## Итерации

Проект редко кончается одним прогоном. `/son-of-orchestrator итерация` проходит
те же фазы по разнице: что меняется в построенном и почему. История лежит по
папкам `.orchestrator/iterations/i1`, `i2` …, а `spec.md` остаётся одним живым
описанием продукта. Номера тикетов сквозные, отчёт прошлой итерации уходит в
её папку, на дашборде прошлые итерации — строками.

Проекты, начатые до этого режима, читаются как есть. Разложить их историю по
папкам — `scripts/migrate.py` (сначала показывает, что сделает).

## Стек

Технические решения принимает агент, из ответов на понятные вопросы. Осей две.

Кто правит контент:

- контентный сайт, который клиент правит сам → WordPress
- админка или своя логика работы с данными → Filament
- лендинг без правок клиентом → статика

Насколько всё живое: если нужны скролл-эффекты, хореография, переходы между
экранами или 3D, стек выбирается под движение — и первая ось на него больше не
отвечает. Обе оси агент называет вслух, а не наследует молча из слова «лендинг».

## Чего навык не делает

- не пишет код до техзадания;
- не режет задачи до того, как задано визуальное направление;
- не отвечает за тебя и не выдумывает содержимое;
- не просит проверять задачи или код;
- не запускает две задачи в одном окне;
- не запускает фоновых агентов без твоего выбора и не даёт одному агенту два тикета;
- не оставляет оплату, ключи и хостинг на финиш;
- не закрывает задачу, не посмотрев результат;
- не показывает округлённый процент там, где сверка ещё не закончена.

## Когда НЕ использовать

Хочешь проектировать вместе шаг за шагом — веди обычный диалог. Задача на правку
одного файла — просто попроси её сделать. Нужен разбор и критика готового — это
работа старшего, а не этого навыка.

### 2.3 — 27 октября 2026

- `probe.mjs` — проверка поведения страницы для приёмки: шаги `text:`, `no:`,
  `click:`, `fill:`, `eval:` и ошибки консоли, ширина окна как у снимков. Идёт

- Установщик больше не оставляет прежнюю копию в папке навыков: она уходит в
  `skill-backups/` рядом. Раньше агент видел её вторым навыком со старым
  описанием, и она могла срабатывать вместо новой.
- Копии, которые оставили прошлые версии установщика, при обновлении
  переносятся туда же.
- Две установки в одну секунду больше не вкладывают копию внутрь прежней.
- Описание навыка — без сравнения с прародителем.

### 2.0 — 29 сентября 2026

- Итерации: `/son-of-orchestrator итерация` — следующий круг по живому проекту,
  история по папкам `iterations/iN/`, одна живая спека.
- Волны: скрипт сам считает, какие тикеты вести параллельно, ловит ошибки
  нарезки и собирает `runbook.md`.
- Волну можно отдать фоновым агентам — каждый тикет в своей копии репозитория.
- Вопросы в три слоя: реальный случай, проверка посылки, развилки. Записанное
  в документах не переспрашивается.
- Одна команда проверки проекта вместо строки в каждом тикете, снимки экранов
  скриптом.
- Дизайн-ревью с пределом: 30 из 40 или два прохода, остаток — в отчёт.
- Дашборд: итерации строками, тикеты по волнам со временем, «можно запустить
  сейчас».
- Проекты прошлой версии работают без переделки.
